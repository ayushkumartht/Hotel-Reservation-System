The main idea: tables are connected by IDs

The bookings table is the centre of the system. It does not copy the customer's name or the room's price. It only stores their IDs:

-- booking 1 : customer 1 booked room 3, the booking was made by staff 2
(1, 1, 3, 2, '2026-09-01', '2026-09-04', 'Completed')

When we need the full details, we JOIN the tables using these IDs: customer 1 = Aman Gupta, room 3 = room 103, staff 2 = Priya Sharma. Because of this, every piece of data is stored only once (no repetition). This is called normalization.

Normalization: why there are 5 tables and not 1

If everything was kept in one big table, the same customer and room details would be written again and again:

booking_idcustomer_namephoneroom_numberprice_per_night
1Aman Gupta98100000011032500
6Aman Gupta98100000012014000
5Arjun Reddy98100000051032500

Aman's phone number is written twice, and the price of room 103 is written twice. If Aman's phone number changes, it must be changed in every row, and if one row is missed the data becomes wrong. Splitting the data into separate tables fixes this problem. This is called normalization:

Normal formRuleHow our tables follow it
1NFEvery cell has only one value. No lists or repeating groups.Each customer has one phone number in one column. No cell holds a list like "101, 102".
2NF1NF, and every column depends on the whole primary key.Every table has a one-column primary key (customer_id, room_id ...), so no column depends on only a part of the key.
3NF2NF, and no column depends on another non-key column.Room price is kept only in rooms and names only in customers. bookings keeps only the IDs.

5. SQL File 1 – Creating the Tables

File: sql/01_create_tables.sql. It creates the database and the 5 empty tables.

Step 1: Create the database

DROP DATABASE IF EXISTS hotel_db;
CREATE DATABASE hotel_db;
USE hotel_db;
  • DROP DATABASE IF EXISTS deletes the old database (if there is one), so we can start fresh every time.
  • CREATE DATABASE makes a new empty database called hotel_db.
  • USE tells MySQL that all the next commands are for this database.

Data types used

VARCHAR(n)Text of up to n charactersfirst_name VARCHAR(50) = 'Aman'

Table 1: customers

CREATE TABLE customers (
    customer_id   INT PRIMARY KEY,
    first_name    VARCHAR(50)  NOT NULL,
    last_name     VARCHAR(50),
    phone         VARCHAR(15)  NOT NULL UNIQUE,
    email         VARCHAR(100) UNIQUE,
    city          VARCHAR(50)
);
  • customer_id is the Primary Key: every customer gets a different number.
  • Phone is stored as VARCHAR, not INT, because we never do maths on phone numbers and they can start with 0 or +91.
  • phone is NOT NULL UNIQUE: every customer must give a phone number, and it cannot belong to two customers.

Table 2: rooms

CREATE TABLE rooms (
    room_id          INT PRIMARY KEY,
    room_number      VARCHAR(10)  NOT NULL UNIQUE,
    room_type        VARCHAR(20)  NOT NULL,
    price_per_night  DECIMAL(8,2) NOT NULL CHECK (price_per_night > 0),
    status           VARCHAR(20)  DEFAULT 'Available'
);
  • room_id (1, 2, 3 ...) is the ID used inside the database. room_number ('101', '102' ...) is the number written on the door.
  • CHECK (price_per_night > 0) stops a price of 0 or a negative price.
  • DEFAULT 'Available': a new room is Available if we do not give a status.

Table 3: staff

CREATE TABLE staff (
    staff_id    INT PRIMARY KEY,
    staff_name  VARCHAR(50) NOT NULL,
    role        VARCHAR(30) NOT NULL,
    phone       VARCHAR(15),
    salary      DECIMAL(10,2)
);
  • A simple table of employees. A staff member's staff_id is saved in every booking they make.

Table 4: bookings (the most important table)

CREATE TABLE bookings (
    booking_id      INT PRIMARY KEY,
    customer_id     INT  NOT NULL,
    room_id         INT  NOT NULL,
    staff_id        INT,
    check_in        DATE NOT NULL,
    check_out       DATE NOT NULL,
    booking_status  VARCHAR(20) DEFAULT 'Confirmed',
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id),
    FOREIGN KEY (room_id)     REFERENCES rooms(room_id),
    FOREIGN KEY (staff_id)    REFERENCES staff(staff_id),
    CHECK (check_out > check_in)
);
  • It has 3 Foreign Keys. They connect a booking to a customer, a room and a staff member.
  • FOREIGN KEY (customer_id) REFERENCES customers(customer_id) means: the customer_id written here must exist in the customers table.
  • CHECK (check_out > check_in) stops wrong dates, like leaving before arriving.

Table 5: payments

CREATE TABLE payments (
    payment_id      INT PRIMARY KEY,
    booking_id      INT NOT NULL UNIQUE,
    amount          DECIMAL(10,2) NOT NULL,
    payment_date    DATE NOT NULL,
    payment_method  VARCHAR(20),
    FOREIGN KEY (booking_id) REFERENCES bookings(booking_id)
);
  • booking_id is a Foreign Key and UNIQUE. A Foreign Key alone would allow many payments per booking (1 : N). Adding UNIQUE allows only one payment per booking, which makes the relationship 1 : 1.
Why is the order of the tables important? A Foreign Key can only point to a table that already exists. So customers, rooms and staff are created first, then bookings (which points to them), and payments last (it points to bookings).

Part A – Basic SELECT

Q1 Show all customers SELECT * 
SELECT * FROM customers;

* means "all columns". There is no WHERE, so every row is shown. Output: all 10 customers.

Q2 Show all rooms that are available WHERE 
SELECT room_number, room_type, price_per_night
FROM rooms
WHERE status = 'Available';

WHERE keeps only the rows where the condition is true. Here: rooms whose status is Available.

Q3 Show all rooms from costliest to cheapest ORDER BY 
SELECT room_number, room_type, price_per_night
FROM rooms
ORDER BY price_per_night DESC;

ORDER BY sorts the result. DESC = biggest first, ASC = smallest first (ASC is the default). Output: the two Suites (7000) first, then Deluxe (4000), Double (2500) and Single (1500).

Part C – JOINS

Q13 Every booking with customer name and room number INNER JOIN 
SELECT b.booking_id,
       c.first_name,
       c.last_name,
       r.room_number,
       r.room_type,
       b.check_in,
       b.check_out,
       b.booking_status
FROM bookings b
JOIN customers c ON b.customer_id = c.customer_id
JOIN rooms r     ON b.room_id = r.room_id;

Q14 Calculate the bill of each booking JOIN + DATEDIFF 
SELECT b.booking_id,
       c.first_name,
       r.room_number,
       DATEDIFF(b.check_out, b.check_in) AS nights,
       r.price_per_night,
       DATEDIFF(b.check_out, b.check_in) * r.price_per_night AS total_bill
FROM bookings b
JOIN customers c ON b.customer_id = c.customer_id
JOIN rooms r     ON b.room_id = r.room_id;

DATEDIFF(date1, date2) gives the number of days between two dates. Bill = nights × price_per_night. The price comes from rooms, the dates from bookings.

Part E – View

Q21 Create a view of booking details CREATE VIEW 
CREATE OR REPLACE VIEW booking_details AS
SELECT b.booking_id,
       CONCAT(c.first_name, ' ', c.last_name) AS customer_name,
       r.room_number,
       r.room_type,
       b.check_in,
       b.check_out,
       DATEDIFF(b.check_out, b.check_in) AS nights,
       DATEDIFF(b.check_out, b.check_in) * r.price_per_night AS total_bill,
       b.booking_status
FROM bookings b
JOIN customers c ON b.customer_id = c.customer_id
JOIN rooms r     ON b.room_id = r.room_id;

A view is a saved query that behaves like a table (a "virtual table"). It does not store data again. CONCAT joins first and last name into one text.

Q22 Use the view SELECT FROM VIEW 
SELECT * FROM booking_details;

Now this one short line gives the full booking details. This is the same data shown on the All Bookings page.

UPDATE ... SET ... WHERE changes existing rows. Always use WHERE, otherwise every row is changed.

UPDATE staff
SET salary = salary * 1.10
WHERE staff_id = 2;

The new value is calculated from the old value: 25000 × 1.10 = 27500.

Q26 Delete the cancelled booking DELETE 
DELETE FROM bookings
WHERE booking_id = 5;

Booking 5 has no payment, so it can be deleted. If we try to delete booking 1, MySQL stops us, because payment 1 still points to it (Foreign Key):

ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails
Tip for MySQL Workbench: all UPDATE and DELETE queries use the Primary Key in WHERE (WHERE booking_id = 5), so they also work when "Safe Updates" mode is on.

10. Viva Questions

Short answers to questions that are often asked about this kind of project.

What is a Primary Key? Give an example.

A column that uniquely identifies every row. It cannot be NULL or repeated. Example: customer_id in customers.

What is a Foreign Key? Why do we need it?

A column that points to the Primary Key of another table. It connects tables and stops wrong data, for example a booking for a customer that does not exist. Example: bookings.customer_id.

How many entities and relationships are there in your ER diagram?

5 entities (customers, rooms, staff, bookings, payments) and 4 relationships: MAKES (1:N), RESERVED (1:N), HANDLES (1:N) and HAS (1:1).

How did you make the bookings–payments relationship one-to-one?

By making payments.booking_id both a Foreign Key and UNIQUE. So one booking can have only one payment.

Why is the total bill not stored in the bookings table?

Because it can be calculated: DATEDIFF(check_out, check_in) * price_per_night. Storing it would repeat data and it could become wrong if the price or dates change.

What is the difference between WHERE and HAVING?

WHERE filters rows before grouping. HAVING filters groups after GROUP BY and can use COUNT, SUM etc.

What is the difference between INNER JOIN and LEFT JOIN?

INNER JOIN shows only rows that match in both tables. LEFT JOIN shows all rows of the left table, with NULL where there is no match (used in Q15 to find customers with no booking).

What is a view?

A saved SELECT query that works like a virtual table. It does not store data again. Example: booking_details.

Which normal form are your tables in?

Third Normal Form (3NF): every column holds one value (1NF), every column depends on the whole Primary Key (2NF), and no column depends on another non-key column (3NF). For example, room price is only in rooms, not in bookings.
